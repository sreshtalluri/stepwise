Current Architecture (as of 2026-03-26)
========================================

PIPELINE (Python/FastAPI on Modal)
──────────────────────────────────
1. yt-dlp downloads video (TikTok, Instagram, YouTube)
2. MediaPipe Pose Landmarker extracts 3D pose per frame
3. Outputs DUAL coordinates per frame:
   - joints: image-space coords (x=(lm.x-0.5)*1.8, y=(1-lm.y)*1.8)
     → pixel-perfect alignment with video for ghost overlay
   - joints_3d: world-blended coords (image pelvis position + world offsets in meters)
     → correct 3D body proportions for perspective views
4. Beat detection via librosa
5. Difficulty scoring (per-frame joint velocities)
6. Foot contact heuristic (flat/heel/toe/airborne/slide)
7. Uploads pose JSON + video MP4 to Cloudflare R2
8. Returns result with signed video URL

FRONTEND (Next.js 14 + React Three Fiber)
──────────────────────────────────────────
1. Landing page: paste URL → submit
2. Processing status polling (GET /api/status/:jobId)
3. Result fetched, transformed (joints array → Record, difficulty segments)
4. Viewer with 8 presets:
   - Presets 1,2,3,4,6,7,8: Three.js 3D skeleton using joints_3d (world-blended)
   - Preset 5 (Ghost): 2D HTML Canvas overlay using joints (image-space)
5. Timeline: beat markers, loop regions, speed control, keyboard shortcuts
6. Audio sync with video playback speed

DATA FLOW
─────────
User pastes URL
  → POST /api/process { url }
  → Pipeline (Modal): download → extract → analyze → store
  → GET /api/status/:jobId (poll until complete)
  → GET /api/result/:jobId (transforms pipeline schema → frontend schema)
  → Viewer renders

KEY DESIGN DECISIONS
────────────────────
- Ghost overlay uses 2D Canvas (not Three.js) for pixel-perfect video alignment
- Pipeline outputs both coordinate systems to serve different view needs
- Video stored on R2 (no egress fees, ~$0.015/GB/month)
- MediaPipe image-space landmarks for ghost, world-blended for 3D proportions
- 8 curated view presets instead of modular grid (simpler, better UX)
